# ClipDrive

מדביקים לינק יוטיוב, בוחרים MP4 או MP3, ובוחרים לאן: תיקייה בגוגל דרייב, או הורדה ישירה
למחשב.

כלי אישי למשתמש יחיד. הממשק בעברית, RTL מלא, מצב בהיר וכהה, ורספונסיבי עד 360px.

---

## מה זה כולל

צנרת אמיתית, עם התקדמות חיה בכל שלב:

1. **הורדה** — `yt-dlp` מוריד את הזרמים הטובים ביותר עד לאיכות שנבחרה.
2. **המרה** — `ffmpeg` עוטף ל-MP4 (העתקת זרמים כשאפשר, קידוד מחדש רק כשחייבים)
   או ממיר ל-MP3 ב-320kbps עם תגיות ID3.
3. **העלאה** — הקובץ עולה לתיקיית הדרייב שנבחרה.

השלבים נפרדים בכוונה: אם שלב נכשל, מה שכבר הושלם נשמר על הדיסק, וניסיון חוזר
ממשיך מהשלב שנפל במקום להתחיל מחדש.

**הורדה ישירה** מדלגת על השלב השלישי — אין לאן להעלות. הקובץ מוכן ברגע ש-`ffmpeg`
סיים, ומד ההתקדמות מראה שני מקטעים במקום שלושה, כי זו הדרך שהמשימה באמת עוברת.
הוא מחכה על הדיסק עד שלוחצים **הורדה ⤓** על הכרטיס — והסרת הכרטיס מהרשימה היא גם
מה שמוחק אותו. משימת הורדה לא צריכה דרייב בכלל, כך שאפשר לעבוד גם בלי לחבר אותו.

## התקנה

### דרישות מוקדמות

```bash
# yt-dlp
pip install yt-dlp

# ffmpeg (כולל ffprobe)
sudo apt install ffmpeg      # Debian / Ubuntu
brew install ffmpeg          # macOS
```

### הרשאות גוגל דרייב

צריך אותן רק כדי לשמור לדרייב. להורדה ישירה אפשר לדלג על כל הסעיף הזה — במסך
החיבור יש "בלי דרייב — רק להוריד למחשב".

1. פתחו פרויקט ב-[Google Cloud Console](https://console.cloud.google.com/) והפעילו את **Google Drive API**.
2. צרו **OAuth client ID** מסוג *Web application*.
3. הוסיפו כ-Authorized redirect URI בדיוק את הכתובת:
   `http://localhost:3000/api/auth/google/callback`
4. העתיקו את `.env.example` ל-`.env` ומלאו `GOOGLE_CLIENT_ID` ו-`GOOGLE_CLIENT_SECRET`.

האפליקציה מבקשת **`drive.file` בלבד** — ההרשאה המצומצמת ביותר שמאפשרת כתיבה.
היא נותנת גישה רק לקבצים ולתיקיות שהאפליקציה עצמה יצרה; שאר הדרייב נשאר בלתי
נראה לה. זו הסיבה שבורר התיקיות מציע ליצור תיקייה מתוך האפליקציה — אין דרך אחרת.

### הרצה

```bash
npm install
npm run dev     # http://localhost:3000
```

### החלטות שכדאי להכיר

- **רכיבי HeroUI v3 בלבד.** הטוקנים של HeroUI (`--accent`, `--surface`, `--muted`
  וכו׳) ממופים ב-`globals.css` לפלטה של העיצוב, כך שהרכיבים מקבלים את המראה
  הנכון בלי לעקוף אותם.
- **משימה אחת בכל רגע.** `MAX_CONCURRENT` ב-`jobs.ts`. המקום בתור שמוצג על כרטיס
  ממתין הוא אמיתי.
- **קובץ של הורדה ישירה חי ב-`~/.clipdrive/work/<id>/`** עד שמסירים את הכרטיס.
  בעלייה, כל תיקיית עבודה שאין לה משימה ברשימה נמחקת — כך שהורדה שנקטעה או משימה
  שנפלה מסוף ההיסטוריה לא משאירות גיגה-בייטים מאחור.
- **מד ההתקדמות דטרמיניסטי תמיד** — אחוז והערכת זמן, אף פעם לא ספינר. ה-shimmer
  מופיע רק על המקטע הפעיל, ושגיאה צובעת רק את השלב שנפל.
- **הפונט Tel Aviv Modernist מוגבל לטווח העברי** (`unicode-range` ב-`globals.css`).
  זה פונט תצוגה שבו הספרה 0 היא עיגול והאותיות הקטנות בגובה גדולות, כך
  ש-"1080p" היה נקרא "1O8OP". העברית נשארת בדיוק כמו בעיצוב; ספרות ולטינית
  עוברות לפונט ממשק. להחזרת הפונט לכל התווים — מחקו את שתי שורות ה-`unicode-range`.
- **שרת ה-MCP מדבר עם האפליקציה ב-HTTP**, ולא מייבא את `jobs.ts`. התור הוא
  סינגלטון בתוך התהליך, כך שתהליך שני שהיה מייבא אותו היה מקבל תור שני ומנותק —
  ClipDrive שנייה שחולקת דיסק אבל לא רשימת משימות. מאותה סיבה גם הראוט
  `/api/mcp` פונה ל-origin של עצמו: נתיב קוד אחד, והראוטים ממשיכים להחזיק את כל
  הוולידציה.
- **נתונים מקומיים** ב-`~/.clipdrive` (טוקן, היסטוריה, קבצי עבודה). לשינוי:
  `CLIPDRIVE_DATA_DIR`.

## שרת MCP — הפעלה של האפליקציה על ידי סוכן

`src/mcp/` הוא שרת MCP שחושף את ClipDrive לסוכן AI: להדביק לינק, לבחור פורמט
ויעד, לעקוב אחרי המשימה, ולקבל את הקובץ. הוא לא מריץ yt-dlp או ffmpeg בעצמו —
**האפליקציה צריכה לרוץ** (`npm run dev`), והשרת מדבר איתה ב-HTTP בדיוק כמו
הדפדפן.

### שתי דרכים להתחבר

**stdio** — הלקוח מריץ את השרת כתהליך בן. זו הדרך שמוגדרת בקובץ `.mcp.json`
שבשורש, כך שכל סשן של Claude Code בתיקייה הזו מקבל את הכלים אוטומטית. ל-Claude
Desktop, הוסיפו ל-`claude_desktop_config.json` (ב-macOS:
`~/Library/Application Support/Claude/`) — עם נתיבים מוחלטים:

```json
{
  "mcpServers": {
    "clipdrive": {
      "command": "/absolute/path/to/clipdrive/node_modules/.bin/tsx",
      "args": ["/absolute/path/to/clipdrive/src/mcp/stdio.ts"],
      "env": { "CLIPDRIVE_BASE_URL": "http://localhost:3000" }
    }
  }
}
```

**HTTP** — `POST /api/mcp` באפליקציה עצמה, לכל לקוח שמעדיף כתובת על פני תהליך:
`claude mcp add --transport http clipdrive http://localhost:3000/api/mcp`.
הראוט מזהה את ה-origin שלו לבד, כך שאין מה להגדיר. הוא קיים רק כשהאפליקציה
רצה — ולכן `.mcp.json` מגדיר דווקא את גרסת ה-stdio: היא עולה תמיד, וכשהאפליקציה
כבויה כל כלי מסביר לסוכן איך להריץ אותה.

אל תפעילו את שתיהן בו-זמנית — הסוכן יראה 11 כלים כפולים.

### הכלים

| כלי | מה הוא עושה |
| --- | --- |
| `clipdrive_status` | האם האפליקציה עונה, האם דרייב מחובר, וכמה משימות בכל מצב |
| `clipdrive_inspect_video` | כותרת, ערוץ, אורך והערכות גודל לכל איכות — בלי להמיר |
| `clipdrive_convert` | יוצר משימה. חוזר מיד; לא ממתין לקובץ |
| `clipdrive_list_jobs` | רשימת משימות עם סינון ועימוד |
| `clipdrive_get_job` | משימה אחת במלואה |
| `clipdrive_wait_for_job` | חוסם עד שהמשימה נגמרת, נכשלת או מושהית |
| `clipdrive_control_job` | השהיה / המשך / ניסיון חוזר |
| `clipdrive_remove_job` | הסרה מהרשימה — **מוחק את הקובץ** של הורדה ישירה |
| `clipdrive_list_drive_folders` | תיקיות הדרייב שהאפליקציה יצרה (רק הן, בגלל `drive.file`) |
| `clipdrive_create_drive_folder` | יצירת תיקייה חדשה |
| `clipdrive_save_file` | מעתיק את הקובץ המוכן לנתיב שתבחרו |

### משתני סביבה

| משתנה | ברירת מחדל | תפקיד |
| --- | --- | --- |
| `CLIPDRIVE_BASE_URL` | `APP_URL`, ואז `http://localhost:3000` | איפה האפליקציה רצה. אין לאפליקציה הגדרת פורט משלה — הפורט מגיע מ-`PORT` של Next, אז אם הרצתם על פורט אחר, כאן אומרים את זה |
| `CLIPDRIVE_DOWNLOAD_DIR` | `~/Downloads`, ואז תיקיית הבית | לאן `clipdrive_save_file` כותב כשלא נותנים נתיב |
| `CLIPDRIVE_SAVE_ROOT` | — | אם מוגדר, אסור לכתוב מחוצה לו |

אם הלקוח שלכם לא תומך בהחלפת משתנים בקובץ ההגדרה, החליפו את
`${CLIPDRIVE_BASE_URL:-http://localhost:3000}` שב-`.mcp.json` בכתובת מפורשת.
